## 结论先行

截至 2026 年 8 月 20 日，`mengtzu.com` 的主要技术性 SEO 阻断已经基本解除。

- 已经闭环并在线生效的部分：
  - `www` 到 apex 归一
  - 根路径 `/` 到 `/zh` 的 308 重定向
  - passage 页面唯一 `<title>` / `<h1>`
  - canonical / hreflang / x-default
  - `robots.txt` / `sitemap.xml`
  - Article / Breadcrumb JSON-LD
  - principle 页相关 passage hub 内链
  - 基础安全头

- 当前主矛盾已经不再是“搜不到 / 抓不到 / 识别不清”，而是：
  1. 内容解释层覆盖率仍低，长尾页面竞争力不足。
  2. 关键词可见度很薄，外部搜索市场尚未形成规模化认知。
  3. 运行时性能仍有优化空间，尤其是文章页 LCP 与未使用 JS。
  4. 外部监控数据不完整，Search Console / Semrush 深度历史还没有形成持续闭环。

一句话判断：技术底座已从“危险”进入“可用”，下一轮增长不该继续把主要精力放在修基础标签，而应切到“内容密度、关键词覆盖、性能细化、监控闭环”。

## 二、当前仍然存在的 SEO 问题

以下问题不是“猜测”，而是当前仍可被证据支持的真实遗留项。

### 1. 长尾页面解释层覆盖率不足

现状：

- 全站 passage 总数：260
- 已有人类编辑解释层的 passage：72
- 覆盖率：`72 / 260 = 27.7%`
- 未覆盖 passage：188

这意味着什么：

- 技术上这 260 个页面都能被索引；
- 但绝大多数页面仍主要依赖原文、直译、基础摘要和模板化结构；
- 从搜索竞争角度看，这不等于“不可索引”，但等于“可索引而不够强”。

根因：

- 技术问题已经先行解决；
- 但能真正提升 query-to-page 匹配度的人工解释层目前只覆盖少数高优先页面。

影响：

- 长尾问题型搜索词承接能力不足
- AI 引用时更容易只抓原文和基础摘要，而不是抓到高质量解释
- 站点整体 topical depth 仍偏浅

优先级：高

### 2. 自然搜索可见度仍然很薄

Semrush 当前成功返回的基础快照（US 数据库）显示：

- Semrush Rank：22,934,392
- Organic Keywords：4
- 这 4 个关键词全部位于 31–70 位区间
- 估算 Organic Traffic：0
- Paid Keywords：0

这意味着什么：

- 站点已具备索引与理解基础，但尚未形成真正的搜索分发规模；
- 现阶段瓶颈不是“页面不存在”，而是“关键词覆盖太少、页面竞争力不够强、外部权威尚弱”。

注意：

- Semrush 更深层的历史与项目审计报告因 API units 不足未能拉取；
- 因此这里是“当前可拿到的最小外部可见度证据”，不是完整流量数据库。

优先级：高

### 3. 文章页 LCP 仍略高于理想阈值

Lighthouse 文章页样本：`/en/books/gao-zi-i/6a-6`

- Performance：87
- SEO：100
- Accessibility：100
- Best Practices：100
- FCP：2.0s
- LCP：2.9s
- TBT：40ms
- CLS：0

问题点：

- LCP 2.9s 高于 Core Web Vitals 的理想线 2.5s
- 主要 LCP 元素是文章页 H1
- 仍存在 render-blocking CSS
- 仍存在未使用 JS

影响：

- 对 SEO 来说，这不是当前最致命的问题；
- 但如果不继续压缩，会影响未来页面体验、抓取渲染效率与移动端稳定表现。

优先级：中高

### 4. 首页与文章页都存在未使用 JS / 阻塞 CSS

Lighthouse 报告共同显示：

- 未使用 JS 节省空间约 58–60 KiB
- 两个较大的 JS chunk 各自约浪费 42%–50%
- 首页与文章页都存在一个约 4.8 KiB 的 render-blocking CSS 请求

这意味着什么：

- 当前技术 SEO 已通过；
- 但运行时代码仍偏重，页面首屏渲染链路还能继续收紧。

更精确地说：

- 首页 `/zh` 的 Performance 为 90，LCP 2.1s，已接近良好；
- 文章页模板比首页更需要性能细化，因为它未来会承接更多长尾搜索入口。

优先级：中

### 5. 外部监控闭环还不完整

现状：

- 本地构建验证已经很强；
- 线上样本抓取也已通过；
- 但外部搜索监控仍有明显缺口：
  - Semrush 深层项目 / 历史 / site audit 数据未完整获取
  - 本次范围内没有 Search Console 查询权限

这意味着什么：

- 现在可以证明“站点结构大体正确”；
- 但还不能持续回答：
  - Google 实际收录了多少页
  - 哪些 query 已经开始获得 impressions
  - 哪些页面存在真实的 coverage / enhancement / indexing 异常

优先级：中高

## 三、什么不是当前问题

以下项在本次审计范围内没有发现持续性问题：

- 站点不可抓取
- `robots.txt` 阻塞主要页面
- `sitemap.xml` 缺失
- `www` / apex 未归一
- 首页入口未归一
- 文章页 title / H1 大面积重复
- canonical 缺失
- hreflang 缺失
- passage 页面 Article / Breadcrumb schema 缺失
- 首页缺少站点级 `WebSite` / `Organization` schema
- Lighthouse SEO 基础项失败

换句话说：如果继续把主要精力投在“补 canonical / 补 robots / 改 title 模板”上，边际收益已经明显下降。

## 四、PDCA：下一轮应该怎么做

### P1：扩展高价值页面的人类解释层

目标：

- 继续把 72 篇扩到 90+ 篇
- 优先覆盖最能承接搜索意图的主题：
  - 性善
  - 四端
  - 仁政
  - 浩然之气
  - 民为贵
  - 舍生取义
  - 王道 / 义利之辨
  - 修身 / 心之官 / 知言 / 知命

为什么先做这个：

- 这是当前最直接影响搜索竞争力的因素；
- 技术底座已经够用，内容解释密度才是增量瓶颈。

建议指标：

- 编辑层覆盖率从 27.7% 提到 35%+
- 每个重点 principle 至少建立 10–20 个强关联 passage 支点

### P2：压缩文章页运行时代码

目标：

- 文章页 LCP 从 2.9s 压到 2.5s 内

优先动作：

1. 排查两个较大的 `_next/static/chunks` 是否能进一步拆分或延迟加载
2. 评估 passage 页面是否有可下沉到服务端或静态阶段的客户端逻辑
3. 收紧首屏 CSS，减少 render-blocking 影响

为什么第二做：

- 这会改善体验，但不会像内容覆盖那样直接决定“有没有更多关键词入口”。

### P3：建立外部搜索监控闭环

目标：

- 从“结构正确”进入“增长可观测”

优先动作：

1. 补齐 Search Console
2. 恢复可用的 Semrush 深层报告能力
3. 形成每周监控面板：
   - 已收录页面数
   - impressions / clicks
   - top queries
   - top landing pages
   - coverage / enhancement 异常

### P4：继续扩充专题页与内链锚点

目标：

- 在现有 related passage hub 基础上继续做厚 principle 页

动作：

- 每个 principle 页继续挂更多高相关 passage
- passage → principle → book → FAQ 的链路进一步做厚
- 让专题页承接更强的 query cluster，而不仅仅做说明页

## 七、最终判断

如果问题被定义为“这个站还有没有技术性 SEO 硬伤”，答案是：当前没有看到新的结构性硬伤，主要硬伤已基本修复并上线。

如果问题被定义为“这个站为什么还没有形成自然搜索可见度”，答案是：

1. 解释层覆盖率还太低；
2. 关键词覆盖仍薄；
3. 性能还有可压缩空间；
4. 外部监控还不完整。

1. 扩展高意图 passage 的人工解释层；

3. 建立 Search Console + Semrush 持续监控；
4. 用专题页和内链把内容网络做厚。
